# Autonomous ML Research Agent for KuaiRand-Pure — Design Spec

Date: 2026-08-28 · Status: approved design, pre-implementation · Track: TechJam 2026 Track 2
Authority: `docs/problem_statement.md` wins over this spec wherever they disagree.

## 1. What we are building and why

The hackathon asks for an **autonomous LLM-driven ML research agent** that runs the full MLE loop
(inspect data → engineer features → train/tune → evaluate → reflect/revise) on KuaiRand-Pure,
writes its own code for every stage, reproduces the organizers' FM baseline, and iterates on its own
until a convergence rule fires. The organizers score the *converged* result once on a hidden test set.

The judging rubric is effectively a spec for the agent's **logs**:

| Criterion | Weight | What the judges read |
|---|---|---|
| Technical Execution | 35% | hidden-test delta over baseline (mean of ΔGAUC, ΔnDCG@5) + robustness visible in run logs |
| Innovation & Problem Insight | 20% | *what* the agent chose to try and *why*, grounded in literature |
| Impact & Relevance (autonomy) | 20% | number of manual interventions during the run |
| Feasibility & Practicality | 15% | total LLM tokens + agent wall-clock, coarse tiers, only if baseline is beaten |
| Presentation | 10% | final event only |

Fixed by the organizers (never change these): label `long_view`; within-user ranking of logged
impressions; metrics GAUC and nDCG@5 as implemented in `kuairand-starter-kit/evaluate.py`; primary =
mean(GAUC, nDCG@5); splits by date from the two standard logs (train 20220408–21 = 1,141,112 rows,
valid 20220422–28 = 124,909, test 20220429–0508 = 170,588); baseline FM validation primary **0.6016**,
hidden-test **0.5946** (5-seed std 0.0008); convergence ε = 0.002 over N = 3 iterations; 50-iteration
cap; 6 h wall-clock ceiling; submission CSV `row_id,user_id,video_id,score`.

Measured facts that shape the design (see `docs/` briefs and the profiler): the kit runs on numpy only
and a full FM run takes 19 s on this Mac (load 2.8 s, encode 3.7 s, 0.85 s/epoch); hidden-test labels
are physically present in the local CSVs; the machine has `/usr/bin/python3` 3.9 + numpy only and a
bare Homebrew `python3.11`; the Anthropic Python SDK requires Python ≥ 3.10.

### Goals
1. A run that starts from a bare skeleton, **writes and verifies the FM baseline itself**, then
   iterates autonomously to a converged, better validation score with zero manual interventions.
2. Every deliverable the rubric asks for is **generated by the harness**: per-iteration hypothesis,
   code diff, metrics, error/recovery events, token and wall-clock accounting, intervention count,
   results table, submission CSV.
3. Hidden-test labels are **architecturally unreachable** by the agent's code.
4. Cheap to develop: the whole loop runs end-to-end on a fake LLM at zero cost.

### Non-goals
- Bonus benchmarks (KuaiRand-1K/27K), a video, GPU support, a web UI, multi-machine execution.
- Beating the baseline by a large margin is the *agent's* job, not something we hand-engineer.
  We may improve the idea bank and prompts; we do not hand-write model code into the run.

## 2. Architecture overview

```
SETUP (once)   raw CSVs ──▶ Data Steward ──▶ workspace: train+valid (labels), test (labels stripped),
                                 │                      data card, idea bank, skeleton pipeline.py, reference/
                                 └──────────▶ SEALED = raw dataset dir + kit, readable only by the harness

LOOP (per iteration, driven by the Conductor)
   Scientist ──hypothesis──▶ Engineer ──pipeline.py──▶ Sandbox ──preds.npz──▶ Scorekeeper
     ▲ (LLM)                  (LLM)   ◀──smoke result──   │ ▲                     │ metrics
     │                                        failure ────┘ └──── patch ≤2 ──── Medic (LLM)
     └──── journal digest · best code · budget left ◀──── Ledger ◀──────────────┘
                                                      new best? converged? (ε 0.002 / N 3 · 50 · 6 h)

FINISH (once)  Gate: best node ─▶ submission.csv ─▶ submit.py --check ─▶ one-shot test score (SEALED labels)
```

Three LLM roles spend tokens (Scientist, Engineer, Medic). Everything else is deterministic Python
with unit tests. Live diagram: https://claude.ai/code/artifact/c32db92c-55ad-4ee5-8748-d8a1bbcca990

Mapping to the organizers' Figure 1: *Read the problem* = problem card (Steward, once); *Inspect data*
= data card (Steward) plus any EDA the Scientist asks the Engineer to run inside `inspect_data()`;
*Engineer features* = Engineer edits `build_features()`; *Train + tune* = Engineer edits `train()`;
*Evaluate* = Scorekeeper with the frozen metric; *Reflect + revise* = Scientist. Every hypothesis is
tagged with the stage it targets.

## 5. Data Steward (`steward.py`, `datacard.py`)

`Steward.materialise(run_dir, data_dir, kit_dir)` creates:

```
runs/<id>/workspace/
  data/
    train.parquet    all 19 log columns + row_id (0-based within split)
    valid.parquet    same
    test.parquet     ONLY: row_id, user_id, video_id, date, hourmin, time_ms, duration_ms, tab
    user_features.parquet, video_basic.parquet, video_stat.parquet   (as in the CSVs, typed)
    DATA_CARD.md
  pipeline.py        copied from labrat/templates/pipeline_skeleton.py
  reference/         read-only copies: kit baseline.py, data.py, evaluate.py, README.en.md, baseline_scores.json
  out/  tmp/         writable by the pipeline
runs/<id>/harness/
  valid_labels.npz   user_ids (str), labels (int8) from the kit's data.load(); the Scorekeeper's private copy
  test_meta.npz      user_ids, video_ids (str) for alignment checks; NO labels
```

Rules:
- Row order and split membership are defined by the kit: read `log_standard_4_08_to_4_21_pure.csv`
  then `log_standard_4_22_to_5_08_pure.csv` in file order, partition by `date` into the three ranges,
  preserve order. Assert split sizes (1,141,112 / 124,909 / 170,588) and assert `(user_id, video_id)`
  at every row of valid and test equals the kit's `data.load()` output (a full comparison is cheap).
- Test parquet strips every post-exposure column: `is_click, is_like, is_follow, is_comment,
  is_forward, is_hate, long_view, play_time_ms, profile_stay_time, comment_stay_time,
  is_profile_enter`; `is_rand` is dropped everywhere (constant per file).
- `user_id`/`video_id` are stored as int64 in parquet (the raw values); the harness converts to `str`
  wherever it talks to the kit (`evaluate`, `submit`).
- Nothing under `runs/<id>/workspace/` ever contains test outcome columns. A unit test asserts this.
- The **sealed zone** is the raw dataset directory plus the kit directory; only the Gate and the
  Steward read them. The sandbox denies them (§7) and the leak check forbids referencing them (§6).

Data card (`DATA_CARD.md`, ~150 lines, generated by `datacard.py` from the parquet files + a static
template): file list with columns and dtypes; row counts per split; date windows; label rates per
split for every outcome column; rows/user and rows/video quantiles; duplicate-row counts; feature-table
coverage (100%); sentinels and constants (`is_live_streamer == -124` for 77% of users, `'UNKNOWN'`
strings, constant `is_lowactive_period` / `visible_status`, `duration_ms == 0` for 239 videos,
`music_id == 0` = no music); `hourmin` is hour×100 in UTC+8; `time_ms` epoch ms; the **leak flag** on
`video_stat` (period-aggregate, full-platform statistics computed over a window that includes the
evaluation period — legal to use, must be caveated); `long_view` definition; the metric conventions
(ties by row order, GAUC weights, nDCG@5 zero-positive users included); the organizers' measured dead
ends; the rules the pipeline must follow (§6). Numbers in the card come from computation, not prose.

## 6. Pipeline contract (`labrat/prompts/contract.md`, enforced by the harness)

The only artifact the Engineer edits is `workspace/pipeline.py`. Invocation by the harness:

```
<sandbox-python> pipeline.py --data data --out out/preds.npz --seed 0 --time-budget 300 [--smoke]
```

Requirements:
1. Structure: `inspect_data(data_dir) -> dict`, `build_features(...)`, `train(...)`, `predict(...)`,
   `main()` calling them in that order. Internals are free; the stage functions must exist.
2. Output: `np.savez(out, valid_scores=<float32[124909]>, test_scores=<float32[170588]>)` in the row
   order of `valid.parquet` / `test.parquet` (`row_id` ascending). Optional `meta` (JSON string).
3. Last line of stdout: `LABRAT_STATUS {"status":"ok","model":"...","train_seconds":..,"notes":"..."}`.
4. `--smoke`: subsample training to ≤ 5% of train rows (or ≤ 5% of users), cap epochs/rounds so the run
   finishes in < 90 s, still emit full-length valid/test scores.
5. `--time-budget S`: training must stop gracefully before S seconds and still produce outputs.
6. Determinism: seed numpy / torch / lightgbm / random from `--seed`.
7. Reads only under `--data`; writes only under `out/` and `tmp/`. No network, no subprocesses, no
   package installs, no reading of `reference/` at run time (it is for the Engineer to read, not the code).
8. Validation labels may be used for early stopping, model selection and hyperparameter choice.
   Validation rows must never be training rows. Test columns other than those listed in §5 do not exist.
9. Never use `is_rand`, and never use outcome columns of valid/test as inputs.

Static leak check (`leakcheck.py`), run by the Engineer's smoke tool and again by the Conductor before
every full run — any hit fails the pipeline with the offending line and reason. It is AST-based so
comments and docstrings (e.g. a paper URL) never trigger it: (a) forbidden imports `subprocess`,
`socket`, `urllib`, `requests`, `http`, `pip`, `importlib`, `glob`, `shutil`, `ctypes`;
(b) forbidden calls `os.walk`, `os.listdir`, `os.scandir`, `eval`, `exec`, `__import__`, `open` with a
non-literal or absolute path outside `data/`, `out/`, `tmp/`; (c) string literals containing
`KuaiRand-Pure`, `log_standard`, `log_random`, `kuairand-starter-kit`, `reference/`, `../`,
`harness/`, `sealed`, or starting with `/Users`, `/private`, `/tmp`, `/opt`. The list lives in one
place and is quoted in the contract so the Engineer knows it.

## 7. Sandbox executor (`sandbox.py`)

`Sandbox.run(mode: smoke|full, seed, time_budget) -> RunResult{exit_code, seconds, timed_out,
stdout_path, stderr_path, status_line: dict|None, classification}`.

- `subprocess.Popen([venv_python, "pipeline.py", ...], cwd=workspace, env=MINIMAL, start_new_session=True)`;
  MINIMAL env = `PATH` (sandbox venv bin + /usr/bin:/bin), `HOME=workspace/tmp`, `TMPDIR=workspace/tmp`,
  `PYTHONDONTWRITEBYTECODE=1`, `PYTHONUNBUFFERED=1`, `OMP_NUM_THREADS`/`MKL_NUM_THREADS` = physical cores.
  No `ANTHROPIC_*` variables. stdout/stderr streamed to `nodes/<i>/{stdout,stderr}.log` (per attempt).
- Timeout = `time_budget × 1.25` (smoke: `smoke_timeout_s`); on expiry `os.killpg(SIGTERM)`, then
  `SIGKILL` after 10 s; `timed_out=True`.
- Classification: `TIMEOUT`; `CRASH` (exit ≠ 0); `BAD_OUTPUT` (missing file / keys / wrong length /
  non-finite / wrong dtype — determined by the Scorekeeper's validator, reported back here);
  `LEAK` (static check hit — never runs); `OK`.
- OS-level layer (default on, `--os-sandbox off` to disable): the command is wrapped in
  `sandbox-exec -f runs/<id>/harness/sandbox.sb` rendered from `sandbox.sb.template`:
  deny default; allow process exec/fork; allow file-read on the workspace, the sandbox venv,
  `/usr/lib`, `/usr/share`, `/System`, `/Library/Developer`, `/opt/homebrew`, `/private/var/db`,
  `/dev`; allow file-write on `workspace/out`, `workspace/tmp`, `/dev/null`, `/dev/tty`; deny network.
  A setup-time self-test runs a probe script that must (a) import numpy/pandas/torch/lightgbm, (b) fail
  to read `data/KuaiRand-Pure/data/log_standard_4_22_to_5_08_pure.csv`, (c) fail to open a socket.
  If the profile cannot pass the self-test within the implementation task's budget, the run continues
  with the layer off and `run.json` records `os_sandbox: "unavailable"` — the README states this honestly.

## 8. Scorekeeper (`scorekeeper.py`)

`Scorekeeper.score(node) -> ScoreResult`:
1. Load `out/preds.npz`; validate: both keys present; castable to float64; lengths exactly 124,909 and
   170,588; all finite. Any failure → `BAD_OUTPUT` with a precise message (goes to the Medic).
2. Compute `evaluate(valid_users, valid_labels, valid_scores, k=5)` by importing the kit's
   `evaluate.py` from `kuairand-starter-kit/` (imported by path; the file is never copied or edited).
3. Derive: `delta_baseline = primary − 0.6016`, `delta_best = primary − best_so_far`,
   `significant = delta_best > 0.0016` (2σ of seed noise), `is_best = primary > best_so_far`.
4. Sanity: `primary < sanity_floor (0.47)` → `LOW_SCORE` failure (Medic brief: "almost certainly a
   bug — misaligned rows, inverted sign, constant scores"); `primary > sanity_ceiling (0.80)` →
   `SUSPICIOUS`: node marked invalid, never becomes best, no repair, ledgered with the reason (the oracle
   ceiling on validation is 0.848; nothing legitimate gets near 0.80).
5. Persist `nodes/<i>/metrics.json` and `nodes/<i>/test_scores.npy` (float64, unscored).

Baseline reproduction check (iteration 0 only): `|primary − 0.6016| ≤ baseline_tolerance (0.003)`.

## 9. LLM layer (`labrat/llm/`)

### 9.1 Client
- `LLMClient` protocol: `parse(role, system, messages, schema, max_tokens) -> Parsed[T]` and
  `create(role, system, messages, tools, max_tokens) -> Message` plus `usage` on every return.
- `AnthropicLLM`: `anthropic.Anthropic()` (zero-arg; credentials from env or `ant auth` profile);
  model and effort per role from config; adaptive thinking (omit `thinking`; never `disabled`);
  `output_config={"effort": ...}`; `max_tokens` 32k for the Scientist, 64k for tool roles; **every call
  streams** (`messages.stream(...)` + `get_final_message()`) because thinking is on by default and
  large `max_tokens` would otherwise hit HTTP timeouts; structured output via the streaming form of
  parse (`messages.stream(..., output_format=<pydantic model>)` → `get_final_message().parsed_output`);
  server-side refusal fallbacks enabled
  (`betas=["server-side-fallback-2026-07-01"], fallbacks="default"`) and `stop_reason == "refusal"`
  raised as `LLMRefusal`; SDK `max_retries=3`, `timeout=600`, plus our own retry on
  `RateLimitError` / `APIConnectionError` / 5xx `APIStatusError` with exponential backoff
  (5 attempts, 2 s → 60 s, honour `retry-after`); anything else propagates as `LLMError`.
- Prompt caching: system prompt is a list of blocks in fixed order — problem card, contract, data
  card, idea bank, role instructions — with `cache_control: {"type": "ephemeral"}` on the last block;
  the tool list is identical on every call; no timestamps/UUIDs in cached blocks; JSON rendered with
  `sort_keys=True`. Volatile content (journal, code, logs) goes in the user message.
- Usage: every call emits an `llm_call` event with `role, model, effort, input_tokens, output_tokens,
  cache_creation_input_tokens, cache_read_input_tokens, latency_s, stop_reason`.
- `FakeLLM`: scripted responses from a Python module or JSON fixture, keyed by `(role, call_index)`;
  can return parsed objects, tool calls, or raise `LLMError` to test recovery. Selected by
  `labrat run --fake <script>`.
- `toolloop.py`: the manual `while stop_reason == "tool_use"` loop with a hard `max_turns`, parallel
  tool calls executed in order with all `tool_result` blocks returned in one user message, `is_error`
  on failures, tool inputs parsed with `json.loads` semantics (never string-matched).

### 9.2 Scientist (`scientist.py`)
Inputs: system blocks (§9.1) + user message containing: the journal digest (one row per node: id,
title, stage, status, GAUC/nDCG@5/primary, Δbest, significant?, one-line reflection), the insights
and dead-ends lists, the parent (best) node's full `pipeline.py`, the last node's reflection, the last
node's stdout tail (≤ 60 lines) and failure diagnosis if any, and the budget state (iterations used/50,
minutes used/360, consecutive non-improving count, per-iteration training budget and ceiling).

Output schema (pydantic, via `messages.parse`):

```python
class Hypothesis(BaseModel):
    title: str
    stage: Literal["inspect", "features", "train", "evaluate"]
    rationale: str            # why this should help on THIS data; cite journal/data-card evidence
    reference: str            # method/paper (e.g. "BPR, Rendle et al. 2009") or "none"
    expected_gain: str        # e.g. "+0.004 to +0.010 primary"
    risk: str
    success_criterion: str    # e.g. "valid primary > best + 0.002"
    implementation_notes: str # precise, ordered instructions for the Engineer
    parent_node: int          # must equal the current best node under parent_policy="best"
    est_train_minutes: float  # ≤ config.budget_ceiling_s / 60

class ScientistOutput(BaseModel):
    reflection: str           # on the previous node (at iteration 1: on node 0, the baseline reproduction)
    insights: list[str]       # durable learnings appended to the journal
    dead_ends: list[str]      # directions not worth retrying, with the reason
    hypothesis: Hypothesis
```

Iteration 0 does not call the Scientist: its hypothesis is fixed — "Reproduce the official FM baseline:
2-way FM, k=16, Adam lr=0.001, L2 1e-6, batch 8192, ≤40 epochs, patience 4 on validation primary,
fields user_id, video_id, author_id, tab, duration decile" — with `stage="train"`,
`reference="kuairand-starter-kit baseline.py"`.

The Scientist system prompt instructs: propose exactly one change per iteration; prefer the idea
bank's untested, metric-aligned directions; treat gains under 0.0016 as noise; never repeat a dead end;
keep `est_train_minutes` inside the budget; explain rationale in terms the journal supports.

### 9.3 Engineer (`engineer.py`)
Tools (custom, `strict: true`): `read_file(path)`, `write_file(path, content)`, `str_replace(path,
old, new)`, `run_smoke_test()`, `finish(summary)`. Paths are restricted to `pipeline.py` (read/write)
and `reference/*`, `data/DATA_CARD.md` (read only); anything else returns `is_error`.
`run_smoke_test` runs the leak check, then the Sandbox in smoke mode, and returns `{passed, leak_hits,
exit_code, seconds, smoke_metrics (valid GAUC/nDCG@5/primary), stdout_tail, stderr_tail}`.
Loop: `max_turns = 8`. Success = `finish` after a passing smoke test. If turns run out or `finish` is
called without a passing smoke, the harness runs one smoke itself; still failing → node status
`ENGINEERING_FAILED` with the last error (the Scientist sees it next iteration; no Medic).
Prompt inputs: hypothesis, parent `pipeline.py` (pre-loaded in the user message so the first turn
can edit immediately), contract, coding rules. Effort `xhigh`.

### 9.4 Medic (`medic.py`)
Triggered by full-run classifications `CRASH`, `TIMEOUT`, `BAD_OUTPUT`, `LOW_SCORE`. Same tools as the
Engineer. Brief = hypothesis, failure class, tailored guidance (e.g. TIMEOUT: "the run exceeded S s;
reduce epochs/rounds, subsample, or simplify; do not change the hypothesis"), last 150 lines of
stdout+stderr, the current `pipeline.py`. `max_rounds = 2`; each round = tool loop (`max_turns = 6`,
must end with a passing smoke) → full run → re-classify. After the cap the node is `FAILED` with the
Medic's final diagnosis; nothing is silently dropped.

## 10. Conductor (`conductor.py`)

State per node: `PROPOSED → IMPLEMENTED → RAN → SCORED → COMPLETE | FAILED | INVALID`, written to
`nodes/<i>/status.json` after every step (with attempt counters). `labrat resume <run_id>` reloads
`events.jsonl` + status files and continues at the first incomplete step; completed steps are never
re-run (a written `pipeline.py` or `preds.npz` is reused).

Loop:
```
i = 0
while not stop():
    hyp   = fixed_baseline_hypothesis if i == 0 else scientist.propose(state)
    node  = engineer.implement(hyp, parent=best_node)          # ENGINEERING_FAILED → record, i += 1, continue
    res   = sandbox.run(full, budget=min(hyp.est_train_minutes*60, ceiling))
    res   = medic.repair(res) while res.classification not in {OK, SUSPICIOUS} and rounds < 2
    score = scorekeeper.score(node)                            # sets is_best/significant or failure
    ledger.record(node, hyp, diff, res, score, tokens, timings)
    if i == 0 and not reproduced: retry_iteration_0 (fresh Engineer, ≤ 3 attempts total), else i += 1
gate.finish(best_node)
```

Definitions (documented in the README because the problem statement leaves them open):
- **Iteration** = one loop turn, successful or not; counts toward the 50 cap.
- **Convergence**: over *scored* iterations only (a failed iteration has no validation score).
  Let `best_k` be best-so-far after the k-th scored iteration; converged when `k ≥ N` and
  `best_k − best_{k−N} ≤ ε` (ε = 0.002, N = 3). Config `count_failed_as_nonimproving=false` flips this.
- `stop()` = converged, or iterations = 50, or elapsed ≥ 6 h (checked before each iteration and
  before each full run; a run in progress is allowed to finish only if projected within the ceiling).
- **Best-so-far** = highest valid primary among `COMPLETE` nodes (strict `>`); ties keep the earlier node.
- `parent_policy = "best"` (default). Nodes store `parent_node`; `"scientist_choice"` lets the
  Scientist pick any COMPLETE node (Approach B) — implemented as a policy switch, not used by default.
- If iteration 0 never reproduces within tolerance after 3 attempts, the run continues from the best
  attempt and the ledger/journal state `baseline_reproduced: false` prominently.
- Any uncaught exception in a step is caught at the loop level, ledgered as `harness_error`, and the
  step is retried once; a second failure marks the node FAILED and the loop continues. The process
  never exits mid-run except on `KeyboardInterrupt` (which is ledgered as an intervention prompt).

## 11. Ledger (`ledger.py`)

`events.jsonl` — one JSON object per line: `ts` (ISO-8601 UTC), `run_id`, `iteration`, `event`, plus
event-specific fields. Events: `run_started{config}`, `node_started{hypothesis}`,
`llm_call{role, model, effort, usage…, latency_s}`, `tool_call{role, name, ok, seconds}`,
`smoke_run{…}`, `full_run{attempt, classification, exit_code, seconds, timed_out}`,
`repair_round{n, classification_before}`, `score{metrics, delta_best, delta_baseline, significant, is_best}`,
`node_failed{class, diagnosis}`, `node_invalid{reason}`, `node_complete{status}`,
`convergence{k, best_k, best_k_minus_N, converged}`, `intervention{reason}`, `harness_error{step, error}`,
`run_finished{summary}`.

Per node: `hypothesis.json`, `pipeline.py`, `diff.patch` (unified diff vs parent's `pipeline.py`),
`stdout.log`/`stderr.log` per attempt, `metrics.json`, `reflection.md` (the Scientist's reflection
*about* this node, written when the next iteration proposes), `status.json`.

Rendered reports (regenerated by `labrat report` and at run end):
- `journal.md`: per iteration — title, stage, hypothesis rationale + reference, diff stats and a
  collapsed diff, metrics with Δ vs best and baseline, failures and repairs (class → what the Medic
  changed), tokens and minutes for the iteration, and the reflection. Plus running insights/dead-ends.
- `results.md` + `results.json`: baseline vs best (validation); one-shot hidden-test GAUC / nDCG@5 /
  primary and deltas vs 0.6610 / 0.5282 / 0.5946; tokens (input, output, cache_read, cache_creation,
  total) per role and overall; wall-clock total and split into LLM / sandbox / harness; iterations used
  of 50 and how many failed; interventions (count + reasons); GPU-hours = 0; convergence trace.
- `interventions.jsonl` appended only by `labrat intervene --run <id> --reason "…"`.

Wall-clock: run start → `run_finished`, measured by the harness; per-stage timings from events.

## 12. Gate (`gate.py`)

At stop: take the best COMPLETE node's `test_scores.npy`; write `submission.csv` with header
`row_id,user_id,video_id,score`, ids as the original strings, scores formatted `%.9g` (enough to avoid
rounding-induced ties); run `python3 kuairand-starter-kit/submit.py --check --split test --data_dir
data/KuaiRand-Pure/data runs/<id>/submission.csv` and require exit 0; then compute the one-shot test
score by reading the CSV back with the kit's `read_submission` and calling the kit's `evaluate` on the
kit's `data.load()['test']` labels — exactly what an organizer would do with the file. Record it in
`results.json` with `scored_once: true` and the timestamp. The Gate is the only code path that touches
test labels; it runs once per run and refuses to run twice (`gate_done` marker) unless `--force`.

If no node is COMPLETE, the Gate writes a submission from the last valid attempt (or random scores as
an absolute fallback) and records `fallback: true`.

## 14. Testing strategy

Unit tests (pytest, harness venv, no API, no network):
- `steward`: split sizes; alignment with kit `data.load()`; test parquet has no outcome columns;
  data card contains computed numbers; idempotent re-materialisation.
- `leakcheck`: each forbidden token is caught; the skeleton and fixture pipelines pass.
- `sandbox`: runs a fixture; timeout kills the process group; minimal env has no `ANTHROPIC_*`;
  classification per exit path; (if available) sandbox-exec self-test passes.
- `scorekeeper`: validator rejects wrong length / NaN / missing key; metric equals the kit's on a
  known input; floor/ceiling/significance flags; best-so-far tie rule.
- `conductor`: convergence maths on synthetic histories (both failed-iteration policies); caps;
  resume from every step; iteration-0 retry policy.
- `ledger`: event schema; journal/results render from a fixture run; tokens/wall-clock sums.
- `gate`: CSV passes the kit's `--check` on random scores; refuses a second run; one-shot score equals
  the kit's `--score --split test` on the same file.
- `llm`: FakeLLM scripting; tool loop turn cap; parallel tool results in one message; retry/backoff
  on simulated 429; refusal → `LLMRefusal`; structured parse errors surfaced.

End-to-end dry run (`labrat run --fake tests/fixtures/dry_run.py --max-iterations 3`): the fake
Engineer writes a real FM pipeline at iteration 0 (fixture; reproduces 0.6016 ± 0.003), a lower-scoring
popularity variant at iteration 1, and at iteration 2 a pipeline that crashes on the full run and is
fixed by the fake Medic. Assertions: journal/results/submission exist, `submit.py --check` passes,
token/wall-clock fields are populated, the convergence trace is correct. Runtime ≈ 2–3 min.

Live checks (real API, after the dry run is green): `labrat run --max-iterations 2` (~$2), then a full
run.

## 16. Rulings and assumptions (reversible; state them in the README)

1. The random-exposure log is **not** training data (it lies inside the val/test window). The data card
   describes it; the Scientist may propose using it only for unbiased *analysis* reported in the journal.
2. `video_features_statistic` is legal but flagged as a period-aggregate prior; the agent may use it and
   must caveat it in the hypothesis rationale.
3. Evaluation rows are never deduplicated or reordered; deduplicating training rows is the agent's choice.
4. `evaluate.py`, `data.py`, `submit.py` are never modified; the harness imports/invokes them.
5. Iteration and convergence definitions as in §10.
6. LLM: Anthropic API, `claude-opus-5` for all roles by default; provider is behind `LLMClient`.
7. Compute: this Mac only (CPU/MPS); GPU-hours reported as 0.
8. The final run is executed by us with zero `labrat intervene` calls as the goal; any intervention is
   recorded truthfully.
9. Team/contributions section of the README is filled in by the user.

## Appendix A — Idea bank (initial contents of `labrat/ideas/idea_bank.md`)

Each entry: stage · idea · why it may help here · reference · cost. Organizers' measured dead ends are
listed at the end so the Scientist does not repeat them.

1. train · Pairwise BPR loss over impressions of the same user (positives vs negatives) instead of
   pointwise logloss · metric is within-user ranking; base rates differ hugely across users/tabs ·
   Rendle et al., "BPR: Bayesian Personalized Ranking from Implicit Feedback", UAI 2009 · low.
2. train · Listwise softmax / LambdaRank-style loss per user session · directly optimises nDCG@5 ·
   Burges, "From RankNet to LambdaRank to LambdaMART", 2010; Cao et al., ListNet, ICML 2007 · low–medium.
3. train · LightGBM with `lambdarank` objective grouped by user, on id target-encodings + user/video
   features · strong tabular learner; handles crosses automatically · Ke et al., LightGBM, NeurIPS 2017 · medium.
4. features · Train-only user history statistics: per-user long_view rate, per-(user, author) affinity,
   per-(user, tab) rate, recency-weighted; computed with time-respecting cutoffs · users have ~30
   train rows each; author affinity is strong in short-video feeds · Zhou et al., DIN, KDD 2018 (motivation) · low.
5. features · Item-side train-only statistics: video long_view rate, video age (`date − upload_dt`),
   author-level rates, smoothed with priors · popularity dominates exposure (Gini 0.73) · low.
6. features · Time features: `hourmin` hour, weekday, days-since-train-start (drift), position within
   the user's day session (rank by `time_ms`) · base rates drift day-to-day · low.
7. features · Tab-aware modelling: tab-specific bias terms or tab × feature crosses (tab 0 = 4%,
   tab 1 = 39%, tab 4 = 49% long_view) · low.
8. features · Duration handling: `duration_ms` log-scale + quantile buckets crossed with user's typical
   watch length; `long_view` threshold flips at 18 s · Zhan et al., D2Q (duration-quantile), KDD 2022 · low.
9. train · Multi-task learning with auxiliary heads on `is_click`, `is_like`, `play_time_ms`
   (shared embeddings) · 11 extra signals; click is 44% and strongly linked to long_view · Ma et al.,
   ESMM, SIGIR 2018; Ma et al., MMoE, KDD 2018 · medium.
10. train · Watch-time regression as an auxiliary/primary signal with censoring at video length ·
    Zhao et al., "Counteracting Duration Bias in Video Recommendation via Counterfactual Watch Time",
    KDD 2024 · medium.
11. train · Sparse/lazy Adam or Adagrad for embeddings (the kit's dense Adam decays every row each
    batch, over-regularising rare ids) · low.
12. train · DeepFM / DCN-v2 on the same fields · Guo et al., DeepFM, IJCAI 2017; Wang et al., DCN-v2,
    WWW 2021 · capacity was measured not to be the bottleneck; medium; low priority.
13. train · Rank-averaging ensemble of two diverse models (e.g. FM + LightGBM) · low, once two models exist.
14. train · Per-user score normalisation / user-weighted loss so heavy users do not dominate (GAUC is
    positive-weighted, nDCG@5 is per-user) · low.
15. inspect · Train→valid drift analysis (label rates, tab mix, new users 2.8% of valid rows) to
    choose time-decay or recency weighting · low.
16. inspect · Duplicate/repeat-exposure analysis (4% of train pairs repeat, up to 22×) → dedupe or
    "seen-before" feature · low.
17. evaluate · Multi-seed confirmation of near-threshold gains (3 seeds) before accepting a new best ·
    low cost when training is fast.
18. features · Video-stat priors (flagged leak-prone period aggregates): use only if caveated; expect
    small gains because video_id embeddings already capture popularity for the 99.8% of test videos seen
    in train · low.

Measured dead ends (kit README/ablation): adding static categorical user/item fields to FM
(0.5940 vs 0.5950); embedding size k ∈ {8, 16, 32} (0.5895 / 0.5902 / 0.5887); first-order terms on
user-only features cancel within-user by construction.
